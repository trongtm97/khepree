# Object storage (S3-compatible — Vietnix / R2)

Apps depend on `ObjectStorage` in `@khepree/storage`, not on a vendor SDK in UI code. Production uses the S3 adapter. Development may use `MockObjectStorage` when credentials are omitted. Production and staging **must not** use the mock: both buckets are required (`validateRuntimeEnv()`).

## Production public media path

```
Browser → S3_PUBLIC_BASE_URL (https://cdn.khepree.com)
       → Cloudflare Worker
       → Vietnix Object Storage (khepree-public)
```

- **`S3_ENDPOINT`** — Vietnix S3 API only (presigned upload, head, private bucket ops). Never used in HTML `src`.
- **`S3_PUBLIC_BASE_URL`** — CDN origin. Public URLs = `S3_PUBLIC_BASE_URL` + `/` + canonical `objectKey`.
- **Database** stores `objectKey` only (e.g. `products/{slug}/…`, `blog/{slug}/…`, `brand/…`, `media/…`) — not full Vietnix or CDN URLs.

## Buckets

| Logical bucket | Env | Browser origin | Contents |
|----------------|-----|----------------|----------|
| public | `S3_BUCKET_PUBLIC` | `S3_PUBLIC_BASE_URL` (CDN) | Marketing images, product media |
| private | `S3_BUCKET_PRIVATE` | presigned URLs only | Installers, CMS bodies, releases |

Legacy R2 env (`R2_*`) is still supported when `S3_*` is unset.

Private **never** falls back to public. Object keys are minted server-side (`createObjectKey` / `pathPrefix`). Client filenames are not trusted.

Use **separate buckets** per environment (`docs/ENVIRONMENTS.md`).

## Public CDN domain

Point `cdn.khepree.com` at a Cloudflare Worker that proxies to the public bucket. Set `S3_PUBLIC_BASE_URL=https://cdn.khepree.com`. Production requires HTTPS. SVG uploads to the public bucket are blocked.

## Private / downloads

`download.khepree.com` should not list the bucket. Browsers receive short-lived presigned GET URLs from `DownloadService` after authorization. Product-scoped objects (`media.context = product:<id>`) require an entitlement.

CMS bodies use private keys such as `prv/content/{entryId}/{locale}/v{n}.md`. Failed DB writes can leave orphan objects; cleanup is operational.

## CORS

Browser **uploads** use presigned PUT. If admin/account upload from a browser origin, set CORS on the **private** (and public, if used) buckets to allow:

- Origins: the admin and account HTTPS origins for that environment (not `*`)
- Methods: `PUT`, `GET`, `HEAD`
- Headers: `Content-Type` and any checksum headers you send

Server-side Node uploads do not need CORS. If all uploads stay server-side, CORS can stay closed.

Presigned **downloads** opened as top-level navigations typically do not need CORS. Fetching a private object from JavaScript on another origin does.

## Backup

Object storage is not a substitute for database backups. Versioning + cross-bucket replication (or vendor object lock) is the usual approach. Restore drill: copy a known object back and complete a download through the app with a test entitlement.

Full data-safety runbook: `docs/DATA-SAFETY.md`.

## Versioning (recommended for production)

Enable **object versioning** on both R2 buckets in the Cloudflare dashboard:

| Bucket | Versioning | Why |
|--------|------------|-----|
| `R2_BUCKET_PRIVATE` | **On** | Installers, CMS bodies — accidental delete/overwrite recovery |
| `R2_BUCKET_PUBLIC` | On (optional) | Marketing assets — lower risk but cheap insurance |

Versioning increases storage for non-current versions. Pair with lifecycle rules (below).

## Retention lifecycle (configure in Cloudflare R2)

| Rule | Suggested setting |
|------|-------------------|
| Abort incomplete multipart uploads | 3–7 days |
| Expire non-current versions | 90 days (tune to compliance) |
| Public marketing assets | No auto-delete without CMS review |

Lifecycle deletes are **irreversible** once non-current versions expire. Coordinate with Postgres `media_assets` and `software_releases` metadata before aggressive expiry.

## Orphan object cleanup

Orphans happen when upload succeeds but DB transaction rolls back, or when rows are deleted without object delete.

**Safe procedure** (quarterly or after major CMS purge):

1. Query object keys from Postgres (`media_assets`, release artifact fields).
2. List bucket keys via `rclone ls` or S3 API against the R2 endpoint.
3. Flag keys with no DB reference — **human review** before delete.
4. For private installers, cross-check `software_releases` and active entitlements.

Do not run blind bucket-wide delete scripts against production. See `docs/DATA-SAFETY.md`.
