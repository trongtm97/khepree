# Spec: Phase 20 — Campaign Status Sync (Privacy-first, opt-in)

## Capability Map

| Module | Responsibility | Depends on |
|---|---|---|
| `campaign-sync` | DB table, backend endpoint (upsert + delete), validation, rate limit, retention | `@khepree/db`, `@khepree/security`, desktop-auth session |
| `notification` | Opt-in completion/attention notification, dedup by (userId, campaignPublicId, stage) | `campaign-sync`, notifications table |
| `desktop-contract` | TypeScript types + client helper for khepree-novel-ai: toggle, coalesce queue, offline retry, delete | `campaign-sync` endpoint |

Build order: `campaign-sync` → `notification` → `desktop-contract`

---

## Objective

Desktop can optionally push an opaque campaign progress snapshot to Khepree so the account page can display completion status and send a notification when a campaign finishes. **Opt-in is explicit, default OFF.** No story content, filenames, or PII beyond user identity ever leave the desktop.

---

## Allowed payload fields

| Field | Type | Notes |
|---|---|---|
| `campaignPublicId` | string | Opaque ID generated by desktop, max 64 chars |
| `appVersion` | string | Semver, max 32 chars |
| `devicePublicId` | string | From lease — used for ownership, not stored in sync row |
| `totalProjects` | integer ≥ 0 | Count of projects in campaign |
| `totalChapters` | integer ≥ 0 | Count of chapters across all projects |
| `countByStatus` | object | `{ pending, in_progress, completed, error }` integers ≥ 0 |
| `overallPercent` | number 0–100 | Aggregate progress |
| `stage` | enum | `"idle" \| "active" \| "completed" \| "error"` |
| `startedAt` | ISO 8601 string | nullable |
| `updatedAt` | ISO 8601 string | Client-side timestamp |
| `completedAt` | ISO 8601 string | nullable |
| `errorCode` | string | Normalized, max 64 chars, no stack trace; nullable |

## Forbidden fields (server must reject if present and flagged)

Novel title, chapter name, author, file path, source text, translation text, prompt, glossary, memory, audit evidence, cookies, browser profile path, account secrets, raw provider response, stack trace.

The server does NOT inspect content semantics — it validates structural shape only. The payload schema is closed: unknown top-level keys are stripped (not rejected) so new desktop versions don't break old server, but forbidden semantic fields are simply never in the allowed schema.

## Backend: `campaign-sync` module

### DB table: `campaign_sync_states`

```sql
id             uuid PK
user_id        text FK → user.id ON DELETE CASCADE
campaign_public_id  text NOT NULL  -- opaque, user-supplied, max 64
product_id     uuid FK → products.id  -- from desktop session scope
app_version    text
total_projects integer
total_chapters integer
count_by_status jsonb   -- { pending, in_progress, completed, error }
overall_percent numeric(5,2)
stage          text  -- idle | active | completed | error
started_at     timestamptz nullable
updated_at_client timestamptz
completed_at   timestamptz nullable
error_code     text nullable
expires_at     timestamptz NOT NULL  -- retention: 90 days from last upsert
created_at     timestamptz DEFAULT now()
updated_at     timestamptz DEFAULT now()
UNIQUE(user_id, campaign_public_id)
```

### Endpoint: `POST /api/v1/desktop/campaign-sync`

- Auth: Bearer desktop access token (existing `readDesktopAccessToken` + `platform.desktopAuth.resolveAccessSession`)
- Ownership: session userId = row userId
- Capability check: `campaign_status_sync_enabled` feature from lease (enforced server-side via entitlement)
- Idempotent upsert on `(user_id, campaign_public_id)` — update if `updated_at_client` >= stored
- Rate limit: 60 req/min per user (new `DESKTOP_CAMPAIGN_SYNC` limit)
- Retention: `expires_at = now() + 90 days` on every upsert
- Audit log: action `campaign_sync.upsert`

Response: `{ ok: true, syncedAt: ISO }` or error.

### Endpoint: `DELETE /api/v1/desktop/campaign-sync/:campaignPublicId`

- Same auth, ownership check
- Hard delete the row
- Audit log: action `campaign_sync.delete`

## Backend: `notification` module

On upsert when `stage` transitions to `"completed"` or `"error"`:
1. Check if user has `campaign_status_sync_enabled` (already verified by upsert gate — same entitlement).
2. Deduplicate: check notifications table for existing row with `channel = "campaign_sync"` and `resourceId = "<userId>:<campaignPublicId>:<stage>"`.
3. If no existing notification, insert one.
4. No email; no outbox event; just an in-app notification row.

## Desktop contract: `desktop-contract` module (khepree-novel-ai)

Types exported as a `.d.ts`-compatible barrel:

```typescript
interface CampaignSyncPayload { /* allowed fields */ }
interface CampaignSyncResponse { ok: boolean; syncedAt: string }

class CampaignSyncClient {
  constructor(opts: { baseUrl: string; getAccessToken: () => Promise<string | null> })
  isEnabled(): boolean  // reads capability from resolved lease
  setEnabled(v: boolean): void  // persists to local store; false = stops queue immediately
  push(payload: CampaignSyncPayload): void  // enqueues; coalesces by campaignPublicId
  flush(): Promise<void>  // send pending, skip if !isEnabled()
  deleteRemote(campaignPublicId: string): Promise<void>
}
```

Queue behaviour:
- Coalesce: latest payload per `campaignPublicId` wins; discard intermediate progress ticks.
- Flush on: app foreground, completion stage, explicit call.
- Offline: store in local queue (persisted), retry with exponential backoff.
- Toggle off: drain queue to memory without sending; do not retry.
- No flush if `!isEnabled()`.

## Success criteria

- [ ] `campaign_sync_states` table exists with UNIQUE(user_id, campaign_public_id)
- [ ] POST endpoint: rejects unauthenticated, wrong-user, missing capability, malformed payload
- [ ] POST endpoint: idempotent on same campaignPublicId (second call updates, not duplicates)
- [ ] POST endpoint: strips unknown fields — forbidden fields never stored
- [ ] DELETE endpoint: ownership-checked, removes row
- [ ] Rate limit 60/min enforced
- [ ] Retention: expires_at set 90 days from upsert
- [ ] Completion notification inserted, deduped (second completion → no second notification)
- [ ] Automated test asserts serialized payload contains none of the forbidden fields
- [ ] Desktop contract: toggle=false stops flush immediately
- [ ] Desktop contract: coalesce — 100 pushes for same campaign → 1 network call

## Boundaries

- **Always:** Validate payload shape with closed schema; ownership check every request; audit log every mutation
- **Ask first:** Changing retention period; adding email notifications; storing additional fields
- **Never:** Store title/chapter/content/path/prompt/glossary; send without opt-in; expose one user's data to another
